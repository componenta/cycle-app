# Componenta Cycle App

Интеграционный пакет для `componenta/cycle` в Componenta-приложении. Он связывает Cycle-сервисы с обнаружением классов, консольными командами и необязательной подготовкой ORM-схемы.

Используйте его в приложении, которому нужно управляемое фреймворком обнаружение Cycle-сущностей. Библиотеки должны зависеть только от `componenta/cycle`.

## Установка

```bash
composer require componenta/cycle-app
```

Версия 3 требует PHP 8.5.13+, App 6, Console 6, Config 4 и Cycle 2. Она использует
общий контракт сборки приложения. Приложения на версии 2 с Config 3 и Console 5
должны обновить эти зависимости одновременно.

Регистрируйте провайдер после рантайм-провайдера Cycle:

```php
return [
    new Componenta\Cycle\ConfigProvider(),
    new Componenta\Cycle\App\ConfigProvider(),
];
```

## Связанные пакеты

| Пакет | Зачем нужен здесь |
|---|---|
| `componenta/cycle` | Содержит репозитории, fetcher-классы, фильтры, typecasts и фабрики времени выполнения. |
| `componenta/class-finder` | Находит сущности и embeddable-классы в настроенных директориях. |
| `componenta/app` | Готовит общий список классов, публикует поколения сборки и запускает bootloaders. |
| `cycle/orm` | Потребляет итоговую ORM-конфигурацию. |

## Что добавляет

- обнаружение сущностей и embeddable-классов;
- locator-сервисы, основанные на настроенном итераторе классов;
- записи `ClassFinderConfigKey::LISTENERS` для `EntityLocator` и `EmbeddingLocator`;
- консольные команды Cycle;
- необязательный участник `cycle.schema` общей сборки приложения.

## Обнаружение классов и ORM-схема

Entity и embedding locators используют общий итератор классов приложения.
Bootloader обнаружения классов уведомляет зарегистрированные listeners.
Команда `db:schema` создаёт конфигурацию ORM-схемы; её также вызывают `db:sync`
и `db:migrate --schema`. Команды миграции и синхронизации остаются отдельными
операциями развёртывания.

## Необязательная подготовка при сборке

По умолчанию подготовка схемы выключена. Включите её явно, если среде сборки
разрешено читать метаданные настроенной базы:

```php
use Componenta\Cycle\App\ConfigKey;

return [
    ConfigKey::PREPARE_SCHEMA => true,
];
```

Пакет регистрирует `Build\SchemaBuilder` через `Componenta\App\ConfigKey::BUILDERS`.
Он читает текущие исходники через общий discovery iterator и создаёт новые
entity/embedding locators, не запуская bootloaders приложения. Общий
`SchemaCompiler` используется и участником сборки, и командой `db:schema`.
Участник передаёт результат в `BuildContext`; пути, публикация поколения и
очистка принадлежат App. Отдельный файл `config/autoload/cycle.local.php`
при общей сборке не создаётся. Команда `db:schema --output=...` сохраняет
существующее поведение записи самостоятельного конфигурационного файла.

Компиляция может читать метаданные таблиц через Cycle DatabaseProvider и выполнять
доверенные атрибуты и schema modifiers. Это не гарантия сборки без доступа к БД.
Compiler не синхронизирует таблицы, не запускает миграции и не копирует записи БД
в артефакт. Выключенный участник фиксирует пропуск, не разрешая discovery и
database services из контейнера.

Порядок выбора схемы при запуске:

1. Явная конфигурация `Componenta\Cycle\ConfigKey::ROOT` / `SCHEMA`, включая
   намеренно пустую схему. При её наличии builder пропускает компиляцию.
2. Совместимый артефакт `cycle.schema` из выбранного при bootstrap `PreparedBuild`,
   если `PREPARE_SCHEMA` включён.
3. Прежнее поведение Cycle при отсутствии конфигурации: пустая схема.
   Отсутствующий артефакт не запускает обращающуюся к БД компиляцию во время запроса.

Непереносимые значения, включая runtime-объекты и closures, приводят к явному
пропуску этого необязательного артефакта. Для них используйте явную конфигурацию
схемы времени выполнения. Ошибки discovery и compiler передаются вызывающему
коду и не позволяют опубликовать новое поколение.
Если развёртывание требует подготовленную схему, включите
`ConfigKey::SCHEMA_ARTIFACT` в список обязательных артефактов App: пропуск или
отсутствие схемы заблокирует активацию. Не требуйте этот артефакт, если намеренно
используете явную конфигурацию схемы.

Пересобирайте приложение при изменении mappings, schema modifiers или значимой
конфигурации БД. Долгоживущие workers используют выбранное поколение до перезапуска.
Пакет не следит за метаданными БД и не пересоздаёт артефакты в обслуживающих процессах.

## Границы

Этот пакет не должен содержать поведение работы с базой, нужное рантайм-потребителю напрямую. Репозитории, data fetchers, фильтры, typecasts и фабрики времени выполнения принадлежат `componenta/cycle`.
